# AI 软件商店 
## 1. 目标

实现一款类似 Choco / Winget 的 Windows 软件商店，客户端使用 `C# .NET Framework 4.7.2 + WinForms`，服务端使用 `Go`，文件分发通过 `nginx internal` 转发，服务端不直接输出安装包文件。

核心原则：

- 客户端负责展示、下载、安装、卸载、更新和用户交互。
- 投稿者可提交可执行安装包，安装过程由脚本驱动。
- 进度、状态、错误必须通过统一协议回传给客户端。
- 服务端负责账号、投稿、版本、元数据、下载记录、更新检查和文件索引。

## 2. 客户端主界面

启动后主界面只保留：

- 一个传统 `ListBox`
- 一个菜单栏

菜单栏包含：

- 文件
  - 投稿软件
  - 个人中心
  - 退出
- 帮助
  - 关于
  - 检查更新

主列表展示格式固定为：

`软件名称，版本：x，作者，x，发布时间：x，下载量：x，评价：x星，xx个评分`

其中“评价”的 `x星` 表示当前软件全部有效评分的平均星级，按统一规则四舍五入到 1 位小数展示；没有评分时显示为 `暂无评分` 或 `0星`，实现时二选一并保持一致。

下载量和评分都是软件级统计，不随新版本发布而清零。新版本继承当前累计下载量，评分继续按同一个 `software_id` 聚合。

规则：

- 仅用传统 `ListBox`
- 逗号分隔展示信息
- 未安装时，回车打开下载窗口
- 已安装且本地版本低于服务器最新版本时，回车执行更新
- 已安装且本地版本不低于服务器最新版本时，回车启动软件
- 未在规范中明确的回车行为默认无动作
- 右键菜单第一项按状态显示为下载/更新/启动，另包含查看简介、更新日志、评分、卸载

## 3. 下载窗口

用户在主列表选择软件后，回车或右键下载/更新打开一个非阻塞窗口；已安装且无需更新的软件回车或右键启动会打开本地安装记录中的启动路径。

窗口内包含：

- 只读文本框，用于显示状态
- 进度条
- 暂停按钮
- 取消按钮

行为：

- 下载和安装应在后台 worker 中执行
- `Esc` 可将下载转入后台
- 主界面可隐藏到托盘
- 提示文案必须通俗，不暴露过多技术细节

客户端下载软件时必须支持进度显示。
客户端自身更新下载时也使用同样的进度展示逻辑。

## 4. 更新日志窗口

右键“更新日志”后打开独立窗口：

- 标题固定为 `更新日志`
- 窗口内只有一个 `ListBox`
- `Esc` 返回软件主界面，并恢复进入时焦点

规则：

- `ListBox` 按版本列出日志
- 回车进入对应版本的详细日志窗口
- 详细日志窗口只有一个只读文本框
- 文本框非自动换行
- `Esc` 返回版本列表窗口，并保留进入时焦点

## 5. 个人中心

首次打开个人中心且未登录时，先弹出登录/注册入口窗口，包含：

- 登录
- 注册

登录成功后进入个人中心主窗口。个人中心主窗口同样采用 `ListBox` 风格。

主菜单项：

- 用户昵称
- 编辑个人资料
- 修改密码
- 我的投稿
- 退出登录

回车规则：

- 仅对明确标注的项目在回车后打开新窗口
- 其他项回车无动作

退出登录：

- 先退出登录
- 再弹出消息框
- 消息框关闭后返回主界面

### 5.1 登录/注册约束

- 账号包含用户名和密码
- 注册时有昵称输入框
- 用户名可用于登录
- 昵称仅用于展示，不可用于登录
- 昵称最多 10 个字符
- 用户名最多 20 个字符
- 密码 6 到 20 个字符
- 这些限制必须写在输入框的提示文本中

注册完成后自动登录。
登录/注册成功或失败都必须弹消息框。
输入有误时不得销毁当前对话框。

### 5.2 编辑个人资料

窗口包含：

- 用户名输入框
- 昵称输入框
- 保存设置按钮
- 取消按钮

### 5.3 修改密码

窗口包含：

- 旧密码
- 新密码
- 重复新密码
- 修改按钮
- 取消按钮

### 5.4 我的投稿

“我的投稿”也是纯 `ListBox` 窗口。

列表显示格式：

`软件名称，版本：x，发布时间：x，下载量：x，评价：x星，xx个评分，状态：草稿/上架`

回车后打开项目右键菜单：

- 删除
- 上架 / 转草稿
- 编辑

`Esc` 返回个人中心，并恢复进入时焦点。

## 6. 投稿流程

投稿必须先登录。

投稿入口为“投稿软件”菜单项，点击后打开投稿窗口。

投稿窗口包含：

- zip 文件选择
- 上传按钮
- 投稿说明按钮
- 取消按钮

点击“投稿说明”打开只读说明窗口，详细解释投稿规则。

### 6.1 投稿状态

投稿包上传并校验通过后，默认状态为 `草稿`。

投稿者可手动切换：

- 草稿 -> 上架
- 上架 -> 草稿

不需要管理员审核。

### 6.2 可编辑范围

投稿者可编辑现有软件的：

- 软件名称
- 简介

不可原地修改的内容：

- 版本号
- 安装包内容
- install / uninstall / update 脚本
- hash
- 更新日志
- 发布时间

这些内容如需更改，必须发新版本。

第一个版本上传并校验通过后保存为 `草稿`，需要投稿者在“我的投稿”中手动上架。

已有软件上传新版本时，投稿者仍从文件菜单进入“投稿软件”并选择新版本投稿包。客户端和服务端都要求新版本号必须高于当前版本；上传成功后新版本直接进入 `上架` 状态，不再需要手动上架，也不会在“我的投稿”里新增一条历史版本记录。“我的投稿”按软件显示最新版本。

## 7. 投稿包格式

投稿者提交的是一个 zip 包。

zip 根目录必须至少包含：

- `aishop.json`
- `install.ps1`
- `CHANGELOG.txt`

这些必需文件必须直接位于 zip 根目录，不能包在二级目录中。例如打开 zip 后应直接看到 `aishop.json`、`install.ps1` 和 `CHANGELOG.txt`。

建议支持：

- `uninstall.ps1`
- `update.ps1`
- 其它任意文件

由于服务器带宽有限，建议投稿者把较大的安装程序上传到 GitCode 或其它可靠平台。投稿 zip 内可以只存放 `aishop.json`、`CHANGELOG.txt` 和部署脚本，由 `install.ps1` 在执行部署流程时自行下载真实安装包并安装。

### 7.1 `aishop.json`

示例：

```json
{
  "id": "author.software-name",
  "name": "软件名称",
  "version": "1.0.0",
  "author": "作者名",
  "summary": "一句话简介",
  "requiresAdmin": false,
  "install": "install.ps1",
  "uninstall": "uninstall.ps1",
  "update": "update.ps1",
  "updateMode": "script"
}
```

约束：

- `id` 唯一且不可变
- `name` 可改，但仅通过投稿者编辑软件信息
- `version` 必须与包内版本一致
- `summary` 为简介
- `install` 必须存在
- `uninstall` / `update` 如声明则必须存在

## 8. 脚本执行协议

安装、卸载、更新脚本都通过统一的 PowerShell 协议与客户端通信。

客户端在执行脚本前注入辅助模块，投稿者只能调用指定函数上报状态。

建议函数：

```powershell
Set-AIShopStatus "正在准备安装"
Set-AIShopProgress -Percent 30 -Message "正在处理文件"
Register-AIShopUninstall -Command "C:\xxx\uninstall.exe" -Arguments "/S"
Register-AIShopInstallLocation "C:\Program Files\xxx"
Register-AIShopLaunchPath -Path "C:\Program Files\xxx\xxx.exe" -Arguments ""
Complete-AIShopInstall
Fail-AIShopInstall "安装失败"
Test-AIShopCancel
```

通信方式：

- 辅助函数向 stdout 输出 `AISHOP_EVENT` 前缀的 JSON 行
- 客户端读取 stdout 并更新 UI
- 普通 stdout / stderr 记录到日志文件
- UI 只显示面向用户的文字
- `Register-AIShopLaunchPath` 用于登记主程序 exe 或快捷方式 lnk。安装完成后，客户端会用该路径启动已安装且无需更新的软件。

### 8.1 安装流程

1. 请求下载包
2. 校验 hash
3. 解压到临时目录
4. 校验 `aishop.json`
5. 执行 `install.ps1`
6. 监听进度和状态
7. 成功后写入本地安装记录，包括版本、安装位置、卸载命令、启动路径
8. 失败则保留日志

### 8.2 卸载流程

优先级：

1. 使用安装时登记的卸载命令
2. 执行 `uninstall.ps1`
3. 如果都没有，则提示不支持自动卸载

### 8.3 取消与暂停

- 下载阶段支持暂停/继续/取消
- 安装阶段不强制支持真正暂停
- 安装阶段取消只在脚本主动检查取消标记时生效
- 不默认强杀外部安装器

## 9. 更新机制

软件更新分两类：

### 9.1 软件更新

软件版本更新通过新版本投稿实现。

支持模式：

- `script`：使用 `update.ps1`
- `install-over`：直接执行新版本安装覆盖旧版
- `clean-install`：先卸载旧版再安装新版
- `manual`：仅手动处理

### 9.2 客户端自身更新

客户端自身也需要更新，而且更新下载过程必须显示进度，和软件下载一致。

建议单独提供更新器：

- `AI软件商店.Updater.exe`

流程：


0. 软件启动时或点击帮助菜单下的检查更新后检查更新
1. 主程序检查更新
2. 服务端返回最新版本、下载地址、hash 和 changelog
3. 用户确认后主程序退出
4. 更新器下载更新包并显示进度
5. 校验 hash
6. 替换文件
7. 写详细日志
8. 重启主程序

## 10. Changelog 格式

更新日志采用可解析格式，按版本分块。

推荐格式：

```text
=== 1.2.2.2 | 2026-08-18 ===
- 修复安装失败时的清理问题
- 优化下载中断后的恢复

=== 1.1.1.1 | 2026-08-01 ===
- 首次发布
- 支持静默安装
```

规则：

- 每个版本块以 `=== 版本号 | 日期 ===` 开头
- 内容持续到下一版本头或文件结束
- 客户端“更新日志”窗口的版本列表按版本块生成
- 回车后显示对应版本块正文
- 版本号必须与服务端记录一致

## 11. 服务端设计

服务端使用 `Go`。
服务端数据库采用 `PostgreSQL`，不使用 `SQLite`。

职责：

- 用户注册、登录、会话管理
- 投稿上传与校验
- 软件元数据管理
- 版本管理
- 下载统计
- 评分统计
- 更新检查
- 文件索引

文件分发不由 Go 直出，统一走 nginx internal。

### 11.1 文件下载

下载接口由 Go 鉴权和记录下载次数，然后返回 `X-Accel-Redirect`。

nginx 负责内部转发到磁盘上的包文件。

### 11.2 数据表

建议至少包含：

- `users`
- `software`
- `software_versions`
- `ratings`
- `download_records`
- `sessions`

`software` 保存可编辑的软件级信息：

- `id`
- `owner_user_id`
- `name`
- `summary`
- `created_at`

`software_versions` 保存版本级信息：

- `software_id`
- `version`
- `manifest_json`
- `package_path`
- `sha256`
- `changelog`
- `status`
- `created_at`
- `published_at`
- `download_count`

## 12. 本地记录与日志

本地数据建议放到：

`%ProgramData%\AI软件商店\`

目录建议：

- `installed.json`
- `Logs\client.log`
- `Logs\download.log`
- `Logs\install.log`
- `Logs\update.log`
- `Logs\error.log`

日志要求：

- 记录时间
- 记录操作类型
- 记录软件 id 和版本号
- 记录步骤
- 记录用户可见提示
- 记录详细错误
- 记录耗时

UI 上只显示简明信息，详细技术内容只写日志。

## 13. 校验规则

上传 zip 后必须校验：

- 能正常解压
- 不允许路径穿越
- 必须有 `aishop.json`
- 必须有 `install.ps1`
- 必须有 `CHANGELOG.txt`
- `aishop.json` 必须合法
- `id`、`name`、`version`、`summary` 必填
- 版本号不能重复
- 如声明 `uninstall` / `update`，对应文件必须存在
- `CHANGELOG.txt` 必须包含当前版本块
- 包大小和文件数量必须受限

校验通过后：

- 保存文件
- 计算 `sha256`
- 写入数据库
- 第一个版本状态设为 `草稿`
- 已有软件的新版本状态直接设为 `上架`

## 14. 交互约束

- 主界面未明确的回车行为默认无动作
- 所有窗口 `Esc` 退出或返回时必须恢复进入前焦点
- 只读日志窗口不允许编辑
- 消息框用于成功/失败提示
- 输入错误不得直接销毁对话框
- 术语和提示文案尽量面向普通用户

## 15. 评分系统

评分入口为右键菜单中的“评分”。

### 15.1 评分窗口

评分窗口仍然采用 `ListBox`，并包含：

- 已有评分列表
- 发布评分按钮

评分发布窗口中：

- 星级使用 `ComboBox` 选择
- 星级范围固定为 1 到 5
- 评论为可选项
- 用户对同一软件只能保留一条主评分记录
- 用户再次评分时视为编辑自己的原评分，而不是新增一条

### 15.2 列表展示

每条主评分至少显示：

- 昵称
- 星级
- 评论摘要
- 回复数量
- 发布时间，放在列表项最后

### 15.3 开发者回复

开发者可在某个评分下右键回复。

规则：

- 开发者只能回复，不能修改用户原评分
- 对有回复的评分回车后，打开回复列表窗口
- 回复列表窗口仍然采用 `ListBox`
- 回复列表中可以继续回复
- 回复结构允许树状关系，但界面按列表方式展示
- `Esc` 返回上一层窗口，并恢复焦点

### 15.4 数据统计

主界面显示的星级按该软件所有有效主评分的平均值计算，不包含被删除、屏蔽或失效的记录。

推荐规则：

- 所有评分等权计算
- 平均值按 1 位小数展示
- 评分数量单独显示
- 统计数据在评分新增、编辑、删除后实时或准实时刷新
